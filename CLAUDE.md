# Харви — настольный робот-краб ИИ-помощник

Этот файл даёт Claude контекст проекта. Держи его коротким и актуальным.

## Что это
DIY-робот-краб для рабочего стола: компаньон и помощник с добрым характером (ориентир — ВАЛЛ-И).
Шесть ног, две мощные многосуставные клешни, хвост, глаза-дисплеи. Версия корпуса — «Компакт».

## Ключевые решения
- Приводы: шинные Feetech STS (STS3215 C018 12 В на ногах, STS3032 на кистях клешней).
- Компоновка v2: плечи клешней (105; ±30), глаза-стебельки на передних углах, хвост за подносом; правила движения — в `модели/корпус/harvey_layout.py` (`RULES`), их соблюдают симуляция и прошивка.
- Бортовая электроника: Raspberry Pi 5 + AI HAT+ («голова»), Pico 2 («спинной мозг» для приводов и датчиков края).
- «Большой мозг» (речь, LLM, зрение) — сначала на домашнем ПК, потом на мини-ПК; связь по Wi-Fi.
- Питание: 3S из банок 21700, зарядка на контактной станции-«гнезде».
- Закупка поэтапно: сначала стенд одной ноги, затем остальные приводы.

## Структура папки
- `заметки/` — документы проекта (Obsidian vault можно открыть на всю папку `harvey`).
- `визуализация/` — 3D-модель и интерактивный двойник (HTML, работают офлайн).
- `модели/` — STL/STEP/CAD: `клешни/`, `хвост/`, `глаза/`, `корпус/` (компоновка v2, рама, правила движения, проверка совместимости — `harvey_layout.py`, `harvey_body_parts.py`), `стенд ноги/`, `стенд кисти/`; `рендер/` — Blender-сцена на столе и сетки для визуализаций; `чертежи/` — ГОСТ из FreeCAD (`make_drawings.bat`). `документы/` — даташиты и PDF. `фото/` — эскизы, фото стенда.
- `код/симуляция/` — MuJoCo/PyBullet-скрипты; мир, физика веществ (`harvey_terrain.py`), адаптивная походка (`harvey_gait.py`), режим «фото» Filament (`--photo`); нужен MuJoCo ≥ 3.15. Мини: `mini_behave.py` — поведение головы по датчикам через настоящую прошивку RP2350 (`mini_sensors.py`, `mini_robot.py`); `mini_brain.py` / `run_brain_sim.bat` — «большой мозг» ведёт Харви в окне MuJoCo (голова связана с мозгом по TCP :8765, мозг открывается в своём окне). `код/прошивка/` — код для Pico 2 и Pi: `pico/` — шина приводов (стенд), `rp2350/` — «спинной мозг» мини (датчики, рефлексы, протокол с Pi; стенд без приводов — `selftest.py` на плате + `bench_pc.py` на ПК), `станция/` — маяк станции на RP2350-Zero (два ИК-светодиода, пачки 0,6 / 1,2 мс). `код/голова/` — Pi Zero 2 W мини: глаза GC9D01, настроение, касания, звук, тело (`body.py`: поведение `behavior.py` + походка `gait.py` → цели 28 приводов в RP2350 50 раз в секунду; размеры ног — `mini_geometry.json` из CAD), поведение (осмотреться, к руке, у края, домой без ПК и в темноте — ось станции по ИК-маяку, метка AprilTag `dock_tag.py` / `camera.py` — направление и расстояние), связь с RP2350 и ПК, калибровка нулей приводов (`calibrate.py` + подставка `calib_jig` → `servo_calib.json`). Установка на Pi — `setup/` (`deploy.py` с ПК по ssh, `provision.py`, `check.py`; настройки места — `HARVEY_*` в `/etc/harvey/head.env`). Симуляция мини ведёт робота этой же головой. `схемы/` — проводка и шины (WireViz + schemdraw, `make_schemes.bat`).
- `код/мозг/` — «большой мозг» на ПК (`harvey_brain`): слово пробуждения «Харви», быстрые команды, LLM через Ollama (ответ JSON: слова, глаза, цель), TCP-сервер для головы на порту 8765; голос готов (этап B): микрофон -> Silero VAD -> GigaAM v2 -> текст, Piper ru_RU -> динамик, полудуплекс (`speech.py`, `get_models.py`); модели вне репозитория (`~/.harvey/models`, путь только ASCII — espeak). Тесты: `python -m pytest -q tests` из `код/мозг` (C:\venvs\harvey-brain). Запуск: `python -m harvey_brain --text` или `--mic` (README).

- На вопросы о структуре и связях («где», «что от чего зависит», «какие заметки про…») сначала `graphify-out/GRAPH_REPORT.md` и `graphify query "<вопрос>"`, потом открывать только найденные файлы.

- Код в графе обновляет git-хук после каждого коммита (без LLM). Заметки и картинки — вручную `/graphify --update`, когда изменений накопится много.

## Качество кода (ub-mode + superpowers)
- Любую правку кода (стенд, прошивка, симуляция, генераторы схем) делать по `.claude/skills/ub-mode/SKILL.md`: сначала тест, который падает, потом минимальная правка, потом чистка. Заметок и документов это не касается.
- Плагин superpowers (включён для проекта в `.claude/settings.json`): новая функция — `brainstorming` → `writing-plans` → `test-driven-development`; ошибка — `systematic-debugging`; перед словом «готово» — `verification-before-completion`.
- Инструменты ub-mode — `C:\venvs\harvey-quality` (исходники `C:\tools\unclebob`): `crapper` (CRAP < 10), `dryer` (дубли ≥ 0,8), `mutator` (мутанты). Для стенда — `код/стенд привода/check_quality.bat` (тесты под coverage в окружении стенда → crapper → dryer; `check_quality.bat mutate sts` — ещё мутанты). Сам `crapper` без готового покрытия на Windows даёт 0 %: он зовёт заглушку `python3` из Microsoft Store. Отчёты — в `.metrics/` (не в git).
- MicroPython-код Pico (`код/прошивка/pico/`) проверяется на ПК через `pc_check.py`; железо — только на стенде.
- Тесты: стенд — `код/стенд привода` (harvey-bench), прошивка RP2350 — `код/прошивка/rp2350` (harvey-bench), голова — `код/голова` (C:\venvs\harvey-head), симуляция мини — `код/симуляция/мини` (C:\venvs\harvey); везде `python -m pytest -q tests`. Пути к файлам вне своей папки в тестах искать и без resolve(), и с ним — иначе mutator даёт ложные 100 %.

## Правила работы
- Источник правды по числам — документы в `заметки/`; при изменении решения обновляй и документ, и этот файл.
- Новые решения записывай в `заметки/Журнал решений.md` (дата, что решили, почему).
- Даташиты: распиновку, напряжения, токи, тайминги и логические уровни не придумывать — брать из `документы/` и указывать источник (документ и пункт или страницу). Непроверенное помечать «предварительно» / «проверить на стенде»; успешная компиляция или симуляция — не доказательство, что железо подключено верно.
