# Голова «Компакт мини» — Pi Zero 2 W

Программа головы управляет глазами (2 круглых дисплея GC9D01), настроением, касаниями крышки, звуком — и телом: поведение и походка шлют цели всех 28 приводов в «спинной мозг» RP2350 по USB 50 раз в секунду. С «большим мозгом» на ПК голова связана по Wi-Fi. Без ПК голова живёт сама: пугается края и рук, радуется поглаживанию, устаёт, когда садится батарея, засыпает от скуки — и сама идёт на зарядку, в том числе в темноте.

![[глаза_выражения.png]]

**ПРЕДВАРИТЕЛЬНО.** Выводы — по [[схемы/README|схемам]]. Всё проверено на ПК; дисплеи, кнопки и звук — на стенде.

## Как устроено

| Файл | Что |
| --- | --- |
| `eyes.py` | рисует глаз 160 × 160 по выражению (10 выражений), моргание, взгляд, плавные переходы; кадр — RGB565 для GC9D01 |
| `gc9d01.py` | драйвер дисплея: запуск по коду Waveshare, окно, кадр кусками ≤ 4096 байт; два глаза на SPI0 CE0 / CE1 |
| `mood.py` | события → выражение: испуг не перебивается мелочами, без событий — сонливость и сон |
| `touch.py` | 4 × TTP223: погладить (3 кнопки подряд за 1,2 с), коснуться (< 0,5 с), подержать (> 1,5 с) |
| `links.py` | RP2350 по USB и ПК по TCP; обрыв — переподключение через 1, 2, 4 … 30 с |
| `audio.py` | aplay / arecord для I2S (INMP441 × 2, MAX98357A), вывод SD усилителя |
| `head.py` | всё вместе: события → настроение → глаза; телеметрия на ПК 5 раз в секунду |
| `behavior.py` | поведение: телеметрия RP2350 + «зрение» → команда корпусу (осмотреться, к руке, у края, подняли, домой) |
| `dock_tag.py` | метка AprilTag станции в кадре (OpenCV, словарь 36h11) → направление и расстояние до неё; без ПК |
| `camera.py` | Camera Module 3 Wide (Picamera2) → метка станции 5 раз в секунду |
| `calibrate.py` | калибровка нулей приводов: две позы → ноль и направление каждого привода в `servo_calib.json` |
| `gait.py` | походка: команда корпусу → углы 28 суставов (трипод, подъём стопы 15 мм, разгон 0,8 м/с², «лечь» −13 мм); размеры ног — `mini_geometry.json` из CAD |
| `servos.py` | номер привода по суставу (ID = 10 × конечность + сустав), позиция STS по углу, сообщение `j` |
| `body.py` | тело: телеметрия, события и «зрение» → поведение → походка → `j` 50 раз в секунду; через 1,5 с после старта — `cal` (калибровка края) |
| `protocol.py` | формат сообщений — общий с прошивкой (`код/прошивка/rp2350/link.py`) |
| `main.py` | запуск на Pi; `--sim` — без железа |
| `setup/` | установка на Pi: `deploy.py` (ПК: копия по ssh), `provision.py` (Pi: пакеты, `config.txt`, служба), `check.py` (Pi: проверка железа и связи) |
| `preview.py` | лист выражений и анимация (`глаза_выражения.png`, `глаза_анимация.gif`) |

Команды от ПК:
- `goal` — цель поведения: `look`, `hand`, `home`, `idle`;
- `emote` — выражение на время;
- `look` — куда смотреть;
- `play` — проиграть звук;
- `j`, `relax`, `hold`, `cal` — голова передаёт их RP2350 как есть.

## Проверка на ПК

```bash
C:\venvs\harvey-head\Scripts\python.exe -m pytest -q tests
```

234 теста, < 7 с.
- **Глаза** сверяются с эталонными картинками `tests/golden/` до пикселя. После намеренной правки рисунка эталоны пересоздаёт команда `python -m tests.test_exact`.
- **Драйвер дисплея** проверяется на имитации SPI: команды при DC = 0, данные при DC = 1, полный код запуска из файла производителя.
- **Связь с ПК** проверяется на настоящем TCP-сервере: обмен в обе стороны и переподключение.

**Поведение** (`behavior.py`) проверяется на простом мире в самих тестах: корпус поворачивается и шагает ровно по
команде, гироскоп показывает этот поворот, маяк и метка станции — по геометрии. Как оно ведёт настоящего робота по его
датчикам — в симуляции: [[код/симуляция/мини/README|Симуляция мини]], раздел «Поведение по датчикам».

- Цели: «look» — осмотреться (6 остановок по 60°), «hand» — подойти к руке и встать в ~9 см, «home» — на станцию.
- Край стола: прочь от датчиков, под которыми пусто, ещё 0,5 с, разворот на 120° — и снова к цели.
- Подняли: стоять, пока все датчики края не видят стол 1 с подряд, потом осмотреться.
- Курс — по гироскопу (`tel["gyr"]`): повороты на угол, при ходьбе курс держится сам.
- Домой — без ПК и в темноте:
  1. Найти станцию: метка в кадре или пачки ИК-маяка.
  2. Повернуться к ней: по метке — сразу, по маяку — пройти сектор туда и обратно и встать на середину.
  3. Выйти на ось станции. Шагом вбок пройти клин, где центральный приёмник видит оба светодиода станции (`tel["axis"]`), туда и обратно и встать на середину клина. Снова повернуться к станции.
  На проходе клина Харви держит станцию перед собой: доворот на шаг вбок, курс против увода держит гироскоп. Если смотреть прямо на маяк и приёмник на оси, то и центр корпуса на оси.
  4. Идти прямо: курс держит гироскоп, при выходе из клина — шаг вбок.
  5. Остановиться по передним датчикам края (площадка ближе стола, снова стол, башенка ближе), отступить на 17 мм, лечь. Нет заряда за 3 с — отойти на 20 см и сразу снова выйти на ось, без поиска; повторить один раз.
- Метка (`dock_tag.py`) даёт только направление и расстояние: под каким углом на неё смотрят, маленькая метка не показывает. Ось станции даёт только маяк.
- Метка проверяется на синтетических кадрах: метка 36h11 нарисована в кадре по известной позе. Направление — ±0,3°, расстояние — ±2 %, в том числе при четверти света. Нужен OpenCV ≥ 4.7 с модулем aruco; на Pi — `sudo apt install python3-opencv`, на ПК — `pip install opencv-python-headless`.
- **Походка** (`gait.py`) — та же, что в симуляции: `код/симуляция/мини/harvey_mini.py` берёт отсюда обратную задачу ног и шаг, и её тест «стопа туда, куда просили» сверяет их с MuJoCo. Сценарии симуляции (`mini_behave.py`) ведёт настоящая голова: `Head` + `Body` + `Behavior` + `Gait`.
- **Проверить на стенде:** нули и направления приводов — `servos.py` считает, что угол сустава в симуляции и в приводе один и тот же; откалибровать камеру по шахматной доске (объектив Wide сильно искажает края) и замерить скорость разбора кадра 1280 × 720 на Pi Zero 2 W.

Качество кода: покрытие 89 %, без тестов только открытие настоящих дисплеев и `main`; самая сложная функция — 9, повторяющегося кода нет.

## Установка на Pi Zero 2 W (Raspberry Pi OS Lite 64-bit, Bookworm или новее)

Пароли и Wi-Fi скрипты не трогают: их вводите вы в Raspberry Pi Imager. Всё из `setup/` — на стандартной библиотеке Python.

1. **Карта.** В Raspberry Pi Imager: Raspberry Pi OS Lite (64-bit); в настройках — имя `harvey`, пользователь и пароль, ваш Wi-Fi, включить SSH и вставить свой открытый ключ (вход по ключу).
2. **Копирование и настройка одной командой с ПК** (из `код/голова`; нужен OpenSSH — в Windows он есть):
   ```bash
   python setup/deploy.py harvey.local --install            # --brain <имя ПК> — если не имя этого ПК
   ```
   `deploy.py` пакует `harvey_head/`, `setup/`, `код/прошивка/rp2350/link.py`, файл запуска дисплея из `документы/` и (если есть) `servo_calib.json` и передаёт по ssh в `~/harvey` на Pi с той же раскладкой папок, что в репозитории. `--install` затем запускает на Pi `provision.py --apply --brain <ПК>` под sudo:
   - пакеты apt (SPI, GPIO, ALSA, OpenCV, Picamera2), окружение `~/harvey/venv` с `--system-site-packages` и `pyserial`;
   - блок `# --- harvey ---` в конец секции `[all]` файла `/boot/firmware/config.txt` (SPI, I2C, I2S, оверлей звука, камера); перед первой правкой — копия `config.txt.harvey.bak`;
   - пользователь входит в группы доступа к железу (только существующие в системе);
   - `/etc/harvey/head.env` (адрес ПК; уже существующий файл не затирается) и служба `harvey-head` с автозапуском.
   Повторный запуск ничего не дублирует. Посмотреть шаги, ничего не меняя: `sudo python3 ~/harvey/код/голова/setup/provision.py --dry-run`. Обновить код головы после правок: `python setup/deploy.py harvey.local` и `sudo systemctl restart harvey-head` на Pi.
3. **Перезагрузить Pi:** `sudo reboot` (оверлеи из `config.txt` включаются при загрузке).
4. **Проверить железо и связь** на Pi: `python3 ~/harvey/код/голова/setup/check.py` — таблица ✓ / ✗ / ?: SPI, карты звука (вывод и ввод), камера, RP2350 (`/dev/ttyACM*`), доступность ПК на порту 8765, служба. Код выхода 0, если всё в порядке.
5. **ПК.** «Большой мозг» (`python -m harvey_brain`, порт 8765) должен быть запущен. Брандмауэр Windows порт 8765 для входящих сам не открывается — разрешите его сами, иначе `check.py` напишет «ПК … не отвечает … (брандмауэр Windows?)».

Настройки, зависящие от места, читаются из переменных окружения (службе их даёт `/etc/harvey/head.env`) поверх `config.py`: `HARVEY_BRAIN_HOST`, `HARVEY_BRAIN_PORT`, `HARVEY_SPINE_PORT`, `HARVEY_ALSA_DEVICE`.

**Проверить на стенде (предварительно, в документах проекта этого нет):**
- Оверлей `googlevoicehat-soundcard` для пары INMP441 + MAX98357A. Если `aplay -l` / `arecord -l` карты не показывают — подобрать другой оверлей и поправить `HARVEY_LINES` в `setup/provision.py`.
- Имя карты ALSA (ожидается `sndrpigooglevoi`): подставить в `HARVEY_ALSA_DEVICE` в `/etc/harvey/head.env`, например `plughw:1,0`, затем `sudo systemctl restart harvey-head`.
- Что RP2350-Zero по USB появляется как `/dev/ttyACM0` (иначе `HARVEY_SPINE_PORT`); VID/PID платы не фиксируются.
- Группы доступа `gpio spi i2c audio video dialout`: `provision.py` добавляет пользователя только в те, что есть в системе (`getent group`), остальные пропускает с сообщением «нет группы … — пропущено». Нужна ли отсутствующая группа (например `gpio` на новой ОС) — проверить на стенде: если глаза/кнопки/звук не работают с «Permission denied», смотреть `id` и права `/dev/spidev*`, `/dev/gpiochip*`.

## Калибровка нулей приводов

Один раз после сборки и после переборки ноги или клешни. Без неё голова считает, что каждый привод стоит нулём к суставу и вращается как в симуляции. Так при сборке не бывает: качалка садится на шлиц как придётся.

```bash
~/harvey/bin/python -m harvey_head.calibrate          # на Pi Zero, RP2350 по USB, main.py на нём запущен
```

1. **Приводы отпускаются.** Харви ставится на калибровочную подставку `calib_jig` (модели/мини, печать ~80 г, 195 × 216 мм) — это поза A:
   - стопы в гнёздах: поворот ноги 0°, бедро горизонтально, голень отвесно;
   - клешни: плечо прямо и горизонтально, предплечье отвесно вниз, губки сомкнуты до упора и стоят кончиком на столбиках;
   - стебельки глаз вертикально.
2. **По очереди для каждой ноги, клешни и глаз:** программа говорит, куда сдвинуть суставы рукой на 15–30°, и запоминает позицию — это поза B.
3. **Расчёт:** направление привода — знак сдвига, ноль — позиция в позе A минус угол позы A. Углы позы A — в `mini_geometry.json` (из CAD).
4. **Проверки:**
   - сустав не сдвинулся (меньше 5°) или привод не ответил — об этом будет сказано, такой сустав не сохраняется;
   - рабочий ход сустава переходит через край 0/4095 — значит, привод там не встанет: переставить качалку на 1–2 зуба шлица.
5. **Итог** — `servo_calib.json` рядом с программой; голова (`main.py`) читает его при старте. В конце приводы держат позу A: если что-то дёрнулось, этот сустав откалиброван неверно.

Проверено на ПК сквозным тестом: настоящий `Spine`, у имитации шины спрятаны свои нули и направления у всех 28 приводов — калибровка находит каждый.

## Проверить на стенде

1. **Дисплеи.** Оба запускаются кодом Waveshare. Поворот картинки (`EYE_MADCTL`) — по тому, как дисплей стоит в стебельке. Нет ли мерцания при съёмке камерой: 3,3 В от Pi нагружены на ~0,35 А, см. [[схемы/README|схемы]], находка 8.
2. **Частота SPI.** Держит ли 32 МГц через провода в стебельке. Если нет — снизить `SPI_HZ`. 30 кадр/с на два глаза — это ~25 Мбит/с.
3. **TTP223.** Режим модуля — прямой выход без защёлки (перемычки A/B): 1 — пока касаются.
4. **Звук.** Имя устройства ALSA и уровень записи. Сигнал SD усилителя на GPIO26 гасит шипение, когда звука нет.
